# P6 — SAA-2 USB 측정 (60분, 22:00부터)

`src/saa2.py`에 `SweepSource` 구현을 만들어 줘. 대상 장비는 SAA-2(NanoVNA V2 계열, HW V2_2, 펌웨어 1.2)다. 아래 통신은 2026-11-22에 실물로 확인한 것이다(macOS, `/dev/cu.usbmodem*`).

## 통신
- pyserial, 115200, timeout 0.5, write_timeout 2. 포트 목록에서 VID 0x04B4 / PID 8을 맨 앞에 둔다
- 식별: 입력 버퍼를 비우고 `00` 8바이트 + `0D`를 쓰면 3초 안에 `'2'` 1바이트
- 범위 설정(리틀엔디언): 시작 Hz `23 00` + 8바이트, 간격 Hz `23 10` + 8바이트, 점 개수 `21 20` + 2바이트, 주파수당 값 1개 `21 22 01 00`. 간격 = (종료 - 시작) / (점 개수 - 1)을 **내림한 정수 Hz**(마지막 점이 종료 주파수를 넘지 않는다. 291점 2000~3000 MHz면 2,999,999,750 Hz에서 끝난다). 0.5초 기다린 뒤 `20 30 00`으로 FIFO를 비운다
- 읽기: `18 30 n`(n은 1~255)을 쓰면 32바이트 패킷 n개
- 패킷: 리틀엔디언 `<6iH`를 오프셋 0에서. 순서는 기준(re, im), S11(re, im), S21(re, im), 인덱스. `S11 = S11채널 / 기준`. 기준이 0이면 오류. S21은 버린다
- 모으기: 패킷을 인덱스 자리에 넣고, 0부터 점 개수 - 1까지 모두 차면 완료. 인덱스 >= 점 개수이면 오류. 전체 40초 제한(실측: 201점 4.4초, 291점 10.5초). 다 못 받으면 부분 데이터를 저장하지 않는다
- 입력 검사: 시작 < 종료, 50 kHz~3 GHz, 점 개수 11~1001. 범위는 Hz로 바꾸기 전에 MHz에서 먼저 검사한다(`1e308` 같은 값도 500이 아니라 한국어 422). 목표 주파수가 실제로 잴 축 안에 있는지도 본다. **이 검사는 모두 장비를 열기 전에 한다**(거절할 요청으로 장비를 USB MODE로 멈추지 않는다)
- 축: 주파수 i = 시작 + i × 간격(정수 Hz). 저장(`f_hz`)했다가 다시 읽은 스윕이 측정한 스윕과 같아야 하고, 이것을 테스트한다

## 이 장비에서 알아 둘 것
- **PC가 범위를 정한다.** 장비 화면의 설정은 쓰이지 않는다. 화면과 같은지 묻는 확인은 두지 않는다
- **읽기 명령을 보내면 장비 화면이 "USB MODE"로 바뀌고 조작이 멈춘다.** 전원을 껐다 켜면 돌아온다. 측정 버튼 옆에 이 안내를 보여 준다. 식별과 화면 받기만으로는 화면이 멈추지 않는다
- **USB로 받는 값에는 장비의 교정이 반영되지 않는다.** `source = usb`인 측정은 요청 값과 관계없이 `cal_mode = unknown`으로 저장한다(카드에 uncalibrated가 붙는다). 이 규칙은 USB 전용 함수가 아니라 저장하는 공통 경로에 둔다
- 종료 주파수가 목표의 1.5배보다 작거나 시작이 목표의 0.5배보다 크면 경고한다. 경고는 입력하는 동안 측정 버튼 옆에 보여 주고(측정 전), 측정을 막지 않는다. 공진이 범위 끝에 가까우면 깊이가 3 dB 미만으로 계산되어 놓칠 수 있다
- 장비 레지스터에 쓰는 것은 위의 범위 설정 4개와 FIFO 비우기뿐이다. 교정 레지스터나 다른 주소에는 쓰지 않는다

만든 스윕은 다른 source와 같이 `service`의 스윕 검사를 거친다(빈 복소값 목록, 허용 범위 밖의 값 포함).

API: `GET /api/ports`, `POST /api/measurements`의 `source=usb`(포트, 시작 MHz, 종료 MHz, 점 개수). 측정 중 중복 요청은 409. 장비 오류는 503이고 아무것도 저장하지 않는다. 어떤 오류에서도(직렬 포트의 `OSError` 포함) 포트를 닫는다. 화면에서 포트를 다시 찾았을 때 고른 포트가 사라졌으면 목록의 첫 포트를 쓰고, 목록이 비면 측정 버튼을 끈다.

## 화면
낱말과 모양은 `p4_frontend.md`를 따른다. 화면 글에서 장비는 "VNA"라고 쓴다(코드 식별자와 파일 이름은 `saa2`).
- 측정 방법의 맨 앞에 `VNA (USB)`를 붙이고 기본값으로 한다: `VNA (USB) | CSV 파일`, 연습을 누르면 `합성 샘플 (연습)`. 입력은 포트, 시작 (MHz), 종료 (MHz), 점 개수 (11~1001)와 "포트 다시 찾기". 포트가 없으면 "연결된 포트가 없습니다. VNA를 USB로 연결하고 다시 찾아 주세요."
- 판정 화면 아래에 **"다음 측정" 띠**를 둔다. 안내: "고친 내용을 적고 다시 측정합니다". 도체 길이 칸(모노폴. 측정 화면의 칸과 같은 값)과 **"같은 설정으로 다시 측정"** 버튼이 있다(p7에서 "바꾼 것" 칸이 더 붙는다)
  - 다시 측정은 **직전에 성공한 USB 포트**와 **지금 범위 칸의 값**(시작, 종료, 점 개수)으로 잰다. 학생이 눌러야 측정한다. 화면이 스스로 다시 재지 않는다
  - USB 측정에 성공한 적이 없으면 버튼 대신 "VNA로 한 번 측정하면 여기서 바로 다시 측정할 수 있습니다"와 "측정 화면으로 →"를 보여 준다
  - 띠에 무엇을 보일지는 순수 함수가 정한다(렌더링 테스트 도구 없이 테스트한다)
- 카드의 `remeasure`에 **"이 범위를 측정 범위에 채우기"** 버튼을 붙인다. 시작·종료 칸만 채운다(점 개수는 그대로, 측정은 학생이 누른다). 성공한 포트를 알면 판정 화면에 머물고(바로 아래 띠에서 다시 잴 수 있다), 모르면 측정 탭으로 옮긴다. 측정 탭이 없으면(시연 모드) 버튼을 두지 않는다
- 테스트: 띠의 세 경우(USB 성공 전, 성공 뒤, 모노폴이 아닌 안테나), 범위 채우기가 점 개수를 바꾸지 않는지, 포트를 알 때와 모를 때 가는 곳, USB 요청의 경로와 본문

## 시간이 남으면: 장비 화면 받기
`GET /api/device/screen?port=`: `20 EE 00`을 쓰면 `<HHB`(폭, 높이, 비트 수 16) 5바이트와 폭×높이×2바이트의 RGB565가 온다(이 장비는 320×240). 헤더는 리틀엔디언이지만 **픽셀은 빅엔디언**이다(실물: `ff e0` 노랑, `84 10` 회색). PNG는 표준 라이브러리로 만든다(의존성을 늘리지 않는다). PNG로 바꿔 돌려준다. 읽기 명령 전에 받아야 측정 화면이 찍히고, USB MODE가 된 뒤에는 그 글자만 찍힌다.

통과 검사: 가짜 포트로 정상 / 식별 실패 / 범위 밖 인덱스 / 시간 초과 / 기준 0 테스트, 범위 설정으로 쓴 바이트가 위와 같은지(2000~3000 MHz, 201점이면 `23 00 00 94 35 77 00 00 00 00`, `23 10 40 4b 4c 00 00 00 00 00`, `21 20 c9 00`, `21 22 01 00`, `20 30 00`), 그리고 **실물 1회 측정이 저장됨**(안 되면 안 됐다고 보고). 2.45 GHz 패치를 2000~3000 MHz, 201점으로 재면 공진이 2445 MHz 근처(±10)에 나온다. 나누어떨어지지 않는 점 개수(291점, 13점)의 축과 목표 검사, 열기 설정(115200 / 0.5 / 2)도 테스트한다.
