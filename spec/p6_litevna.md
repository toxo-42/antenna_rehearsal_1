# P6 — LiteVNA USB (2차 개발 22:10~23:10)

`src/litevna.py`에 `SweepSource` 구현을 만들어 줘. **읽기만 한다.** 스윕·교정 레지스터에 쓰지 않는다.

## 통신
- pyserial, 115200, timeout 0.5, write_timeout 2. 포트 목록에서 VID 0x04B4 / PID 8을 맨 앞에 둔다
- 식별: 입력 버퍼를 비우고 `00` 8바이트 + `0D`를 쓰면 3초 안에 `'2'` 1바이트
- 읽기: `18 30 n`(n은 1~255)을 쓰면 32바이트 패킷 n개
- 패킷: 리틀엔디언 `<6iH`를 오프셋 0에서. 순서는 기준(re, im), S11(re, im), S21(re, im), 인덱스. `S11 = S11채널 / 기준`. 기준이 0이면 오류
- 인덱스 0에서 시작해 연속으로 점 개수만큼 모이면 완료. 인덱스 >= 점 개수이거나 불연속이면 오류. 최대 8회 읽기, 전체 40초 제한. S21은 버린다

## 주파수 축 주의
장비 설정을 읽지 않으므로 사용자가 입력한 시작·종료·점 개수로 축을 만든다. 장비 화면과 다르면 **오류 없이 틀린 결과**가 된다.
- 측정 전에 "장비 화면: 시작 __ / 종료 __ / __점과 같습니까?" 확인을 받는다
- 축의 각 주파수는 정수 Hz로 반올림한다. 저장(`f_hz`)했다가 다시 읽은 스윕이 측정한 스윕과 같아야 하고, 이것을 테스트한다
- 종료 주파수가 목표의 1.5배보다 작거나 시작이 목표의 0.5배보다 크면 경고한다. 공진이 범위 끝에 가까우면 깊이가 3 dB 미만으로 계산되어 놓칠 수 있다

만든 스윕은 다른 source와 같이 `service`의 스윕 검사를 거친다(빈 복소값 목록, 허용 범위 밖의 값 포함).

API: `GET /api/ports`, `POST /api/measurements`의 `source=usb`(포트, 시작, 종료, 점 개수). 측정 중 중복 요청은 409. 어떤 오류에서도 포트를 닫는다.

통과 검사: 가짜 포트로 정상 / 식별 실패 / 불연속 / 시간 초과 테스트, 그리고 **실물 1회 측정이 저장됨**(안 되면 안 됐다고 보고).
(통신 규격은 기존 앱이 Windows COM3에서 수신에 성공한 방식이다. macOS는 미검증)
