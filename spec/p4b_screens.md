# P4-B — 관리와 판정 기준 (40분, p3과 p4-A가 합쳐진 뒤)

관리 화면과 "판정 기준 보기"를 서버부터 화면까지 만들어 줘. 테스트를 먼저 써. 화면의 구조, 낱말, 모양은 `p4_frontend.md`를 따른다.
(p4-A에서 이력 탭을 미뤘다면 이 단계에서 먼저 만든다.)

## API

| 메서드 | 경로 |
|---|---|
| GET | `/api/antennas/overview` (관리 화면용. 안테나마다 `measurement_count`, `last_measured_at`, `last_stage`, `last_resonance_mhz`. 측정이 없으면 0과 null) |
| PATCH | `/api/antennas/{id}` (`name`만 받는다. 다른 필드가 있으면 무시하지 않고 422. 빈 이름 422) |
| DELETE | `/api/antennas/{id}` (딸린 측정까지 한 트랜잭션으로 지우고 `{"deleted_measurements": n}`) |
| DELETE | `/api/measurements/{id}` (그 한 건만 지운다) |
| GET | `/api/criteria?kind` (stage마다 기준 문장 하나. 모르는 `kind`는 422) |

- 이름 수정과 삭제는 없는 id면 404이고 아무것도 바꾸지 않는다. 삭제는 되돌릴 수 없으므로 화면이 먼저 묻는다. 관리 로직은 `src/manage.py`에 둔다
- 시연 모드(p8)에서는 이름 수정과 삭제가 403이다. `overview`와 `criteria`는 읽기라서 허용한다
- 숫자 필드와 id는 p3과 같은 규칙으로 엄격하게 받는다(SQLite 정수 범위를 넘는 id는 404)

### 판정 기준 문장 (`src/criteria.py`)
`GET /api/criteria?kind=`는 `[{"stage": ..., "text": ...}]`를 `good, narrow, offtarget, unmatched, none, invalid` 순서로 돌려준다. **문장의 숫자는 손으로 적지 않고 `models.py`의 상수에서 만든다**(기준이 바뀌면 문장도 같이 바뀐다). 아래의 `{…}`가 상수 자리다.

| stage | 문장 |
|---|---|
| good | 목표 주파수가 S11 {정합 기준} dB 이하인 대역 안에 있고, 그 대역의 폭이 공진 주파수의 {통상 대역폭} % 이상입니다. |
| narrow | 목표 주파수는 S11 {정합 기준} dB 이하인 대역 안에 있지만, 대역의 폭이 공진 주파수의 {통상 대역폭} %({모노폴/패치} 기준)보다 좁습니다. |
| offtarget | 공진은 S11 {정합 기준} dB 이하인 대역을 만들지만, 목표 주파수가 그 대역 밖에 있거나 대역 끝에 걸쳐 있습니다. |
| unmatched | 목표 근처에 공진은 있지만 S11이 {정합 기준} dB까지 내려가지 않습니다. |
| none | 목표 주파수의 ±{후보 창} % 안에 공진이 없습니다. 공진은 주변보다 {공진 최소 깊이} dB 이상 깊고 S11이 {공진 최대 S11} dB 이하인 골입니다. |
| invalid | S11이 +{양의 S11 기준} dB를 넘는 점이 있어 판정하지 않습니다. 교정이나 연결을 확인해야 합니다. |

- 통상 대역폭은 안테나 종류마다 다르다(p1의 값). `none`의 문장은 **모노폴일 때만** 뒤에 한 문장이 붙는다: "도체 길이를 넣었으면 목표 대신 그 길이의 예상 주파수({λ/4 상수} ÷ 길이 cm, MHz)의 ±{예상 창} % 안에서 찾습니다."
- 이 문장들은 검증 담당의 확인이 필요한 글이다. 뜻을 바꾸지 않는다

## 화면
- **관리 탭**: 위 띠의 탭이 측정 / 판정 / 이력 / 관리가 된다. 안내: "이름 수정과 삭제. 삭제한 것은 되돌릴 수 없습니다."
  - 안테나 표: 안테나, 측정(건수), 최근 측정, 최근 판정, 이름 수정 · 삭제
  - 고른 안테나의 측정 표: 시각, 출처, 판정, 공진 주파수, 바꾼 것, 삭제. `limit=200`
  - 삭제 전에 이름 · 측정 건수 · "되돌릴 수 없습니다"를 넣어 묻는다. 이 문장은 순수 함수가 만든다
  - 삭제 버튼은 흰 바탕에 문제색 글자와 테두리
  - 이름을 고치거나 지운 뒤에는 사이드바의 목록과 요약을 다시 읽고, 열려 있던 카드는 비운다(지워진 것을 보여 주지 않는다). 고른 안테나를 지웠으면 남은 첫 안테나를 고른다
  - 안테나가 없으면 "등록된 안테나가 없습니다. 왼쪽에서 먼저 추가해 주세요."
- **판정 기준 보기**: 판정 카드의 상태 표시 옆에 "판정 기준 보기" / "판정 기준 닫기". 누르면 `GET /api/criteria`의 문장을 양호 · 주의 · 문제로 묶어 **그대로** 보여 준다(`invalid`는 문제에 넣는다). 묶는 일은 순수 함수가 한다. 안테나 종류는 그 측정의 안테나 것을 쓴다

## 테스트
- overview: 측정이 없는 안테나(0과 null), 여러 건일 때 가장 최근 측정의 값
- 이름 수정: 정상, 빈 이름 422, `target_mhz`를 함께 보내면 422, 없는 id 404
- 안테나 삭제: 딸린 측정까지 지워지고 건수를 돌려줌, 다른 안테나의 측정은 남음, 없는 id 404
- 측정 삭제: 그 한 건만, 없는 id 404
- 판정 기준: stage 6개가 정해진 순서로 한 번씩, 상수를 바꾸면 문장의 숫자가 따라 바뀜, 모노폴과 패치의 대역폭 숫자가 다름, 패치의 `none` 문장에 "길이"가 없음, 모르는 `kind` 422
- 화면(순수 함수): 삭제 확인 문장, 기준을 세 묶음으로 나누기, 요청 경로와 본문(가짜 `fetch`)

통과 검사: `uv run pytest`, `node --test web/src/*.test.ts`, `npm --prefix web run lint` 통과, `npm --prefix web run build` 성공. 빈 포트와 임시 DB로 띄워 ① 이름을 고치면 사이드바에 반영 ② 측정 한 건 삭제 뒤 이력에서 사라짐 ③ 안테나 삭제 뒤 딸린 측정이 없음 ④ "판정 기준 보기"에 문장 6개가 세 묶음으로 보임. 실제 `antenna.db`로는 삭제를 시험하지 않는다. 직접 띄워 볼 수 없는 항목은 "사람이 확인"으로 남긴다.
