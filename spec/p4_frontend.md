# P4 — 화면 (P2 무렵부터 병렬, 17:30까지)

## P4-A. Figma (30분 제한)
Figma에 데스크톱 1280px 화면 3개를 만들어 줘: ① 측정 ② 판정 카드 ③ 이력·비교.
대상은 안테나를 처음 배우는 학생. 결론이 가장 크게 보이고, 원인은 한 번에 하나씩 읽히게. 상태색은 양호·주의·문제 3개이며 색만으로 구분하지 말고 기호와 글자를 함께 쓴다. 데이터 출처 배지(실측 / CSV / 합성 데이터)를 항상 보이게.

## P4-B. 구현
방금 만든 Figma 화면(링크: ____)을 `web/`에 React + TypeScript로 구현해 줘. 테스트를 먼저 써.

### 데이터
- 응답 타입은 `web/src/types.ts` 한 곳에 `contract/measurement.json`과 같은 모양으로 적는다. `stage`, `source`, `kind`, `cal_mode`는 문자열이 아니라 값 목록 타입으로 둔다
- API가 준비되기 전에는 `web/src/fixtures/measurement.json`을 쓴다. 계약 파일의 `sweep`은 1점뿐이라 그래프를 그릴 수 없으므로, 계약 파일에서 `sweep`만 `make_sample("offtarget_low")`의 스윕으로 바꾼 파일을 `uv run python`으로 한 번 만들어 저장한다(손으로 숫자를 적지 않는다). API가 준비되면 화면은 API만 쓰고, 이 파일은 테스트에만 남긴다
- API 호출은 `web/src/api.ts` 한 곳에 모은다. 오류 응답은 `{"detail": "한국어 문장"}`이고 이 문장을 그대로 보여 준다

### 화면
- ① 측정: 안테나 선택과 추가(`name`, `kind`, `target_mhz`), 교정 상태 선택(`vna` 본체에서 교정함 / `unknown` 확인되지 않음), 합성 샘플 선택 후 측정, CSV 업로드. 샘플 목록에는 샘플의 종류와 목표 주파수를 함께 보여 준다(판정은 선택한 안테나로 한다)
- ② 판정 카드: 서버가 준 문자열을 **그대로** 표시한다. 프론트에서 수치를 다시 계산하거나 문장을 만들지 않는다. 순서는 headline → diagnoses(title, action, evidence, guide) → status
- ① 측정의 도체 길이 칸(선택, 모노폴 안테나를 골랐을 때만 보임): "지금 도체 길이 (cm)". 비우면 보내지 않고 목표만으로 판정한다. 변경 메모와 달리 측정 뒤에도 값이 남는다(자르거나 덧붙였을 때만 고친다). 숫자가 아닌 글이면 보내지 않고 "지금은 길이 없이 판정합니다"라고 알린다(`lengthInput.ts`). 범위는 서버가 검사한다
- ③ 이력: 선택한 안테나의 측정 목록(시각, 출처, 단계, 공진 주파수)과 한 건을 누르면 그 카드 보기까지. 비교는 p7에서 만든다
- 상태색은 카드의 `stage` 값으로만 정한다: `good`은 양호, `narrow`와 `offtarget`은 주의, `unmatched`·`none`·`invalid`는 문제. `invalid`는 "측정 오류"로 표시한다
- 출처 배지는 `source` 값으로 정한다: `usb`는 실측, `csv`는 CSV, `synthetic`은 합성 데이터, `stored`는 "저장된 측정"(원래 출처를 알 수 없으므로 실측이라고 쓰지 않는다)
- 카드 아래에 "쉬운 말로 설명 듣기" 버튼과 "질문하기" 입력칸 자리를 둔다(P5에서 연결, 그때까지는 비활성). 생성된 글에는 "AI 설명(참고용)", 질문의 답에는 "AI가 고른 설명" 표시를 붙인다
- 교정 상태의 기본값은 `unknown`이고, 선택한 값은 탭을 오가도 유지된다
- 측정 요청이 진행되는 동안에는 다른 탭으로 이동할 수 없다. 이력에서 여러 건을 빠르게 누르면 마지막에 누른 측정만 표시한다(늦게 온 응답은 버린다)
- 이력은 `limit=200`으로 요청한다
- 컴포넌트와 함수는 40줄 이하. 큰 배열에 `Math.min(...배열)` 같은 전개를 쓰지 않는다(12만 점쯤에서 `RangeError`)
- 로딩, 빈 목록, 서버 꺼짐 상태를 각각 만든다. 서버 꺼짐은 요청 자체가 실패한 경우와, 개발 서버 프록시가 `detail` 없는 5xx를 돌려준 경우를 모두 포함한다
- `index.html`의 `lang`은 `ko`, 제목은 앱 이름으로 바꾼다
- Vite 템플릿의 데모 화면과 자산(데모 스타일, `hero.png`, 로고 svg, `public/icons.svg`, `web/README.md`)은 지운다
- 새 npm 패키지는 물어보고 추가

### S11 그래프
- SVG로 직접 그린다. 가로축 MHz, 세로축 dB(위가 0)
- 목표선은 `antenna.target_mhz`, 공진 표시는 응답의 `resonance_mhz`와 `s11_db`로 그린다(`null`이면 그리지 않는다). 스윕에서 최솟값을 찾아 표시하지 않는다. -10 dB 선을 그린다
- 세로축 범위는 0 dB부터 스윕 최솟값까지로 하되, 아래쪽은 -30 dB보다 얕지 않고 -60 dB보다 깊지 않게 한다. 범위를 벗어난 값(0 dB보다 큰 값 포함)은 축 끝에 붙여 그린다
- 좌표 계산(값 → 화면 좌표, 축 범위)은 JSX가 없는 `.ts` 파일의 순수 함수로 둔다

### 테스트
새 패키지 없이 Node 내장 테스트 러너를 쓴다. 테스트 파일은 `web/src/*.test.ts`, 실행은 `node --test web/src/*.test.ts`(`web/package.json`의 `test` 스크립트로도 등록). JSX가 없는 `.ts` 파일만 테스트하고, import에는 `.ts` 확장자를 쓴다.
- `stage` 6개 값 → 상태색, `source` 4개 값 → 배지
- 그래프 좌표: 축 양 끝 값, 세로축 범위의 하한 두 경계(-30, -60), 범위를 벗어난 값이 축 끝에 붙는지, 1점뿐인 스윕과 `resonance_mhz`가 `null`인 경우에 예외가 없는지
- fixture가 `types.ts`의 타입으로 컴파일되는지(빌드의 타입 검사가 잡는다)
- 오류 응답 해석: `detail`이 있는 422, `detail`이 없는 5xx, 요청 실패, 200인데 JSON이 아닌 응답
- 요청 경로와 본문(합성 측정, 안테나 추가, CSV 업로드 필드, 이력 쿼리)을 가짜 `fetch`로 검사
- 20만 점 스윕의 축 범위 계산에 예외가 없는지

통과 검사: `node --test web/src/*.test.ts` 통과, `npm --prefix web run lint` 통과, `npm --prefix web run build` 성공. 그리고 서버와 화면을 실제로 띄워 ① 합성 샘플 선택 → 그래프와 카드 표시 ② `open` 샘플처럼 공진이 없는 측정에서 공진 표시 없이 그려짐 ③ 목표가 범위 밖인 안테나로 측정하면 서버의 한국어 안내가 보임 ④ 서버를 끄면 오류 안내 표시. 직접 띄워 볼 수 없는 항목은 "사람이 확인"으로 남기고 통과로 적지 않는다.
