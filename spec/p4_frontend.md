# P4-A — 화면 틀, 측정, 판정, 이력 목록 (60분, P2 무렵부터 worktree에서 병렬)

`web/`에 React + TypeScript로 화면을 만들어 줘. 테스트를 먼저 써. 디자인 도구는 쓰지 않는다. 구조와 모양은 아래에 적힌 대로 한다.
대상은 안테나를 처음 배우는 학생이다. 결론이 가장 크게 보이고, 원인은 한 번에 하나씩 읽히게 한다.
관리 탭과 "판정 기준 보기"는 p4b, VNA(USB) 측정과 "다음 측정" 띠는 p6, "지난 측정 뒤 바꾼 것"과 비교는 p7에서 만든다. 이번에는 자리만 비워 둔다.

## 데이터
- 응답 타입은 `web/src/types.ts` 한 곳에 `contract/measurement.json`과 같은 모양으로 적는다. `stage`, `source`, `kind`, `cal_mode`는 문자열이 아니라 값 목록 타입으로 둔다
- API가 준비되기 전에는 `web/src/fixtures/measurement.json`을 쓴다. 계약 파일의 `sweep`은 1점뿐이라 그래프를 그릴 수 없으므로, 계약 파일에서 `sweep`만 `make_sample("offtarget_low")`의 스윕으로 바꾼 파일을 `uv run python`으로 한 번 만들어 저장한다(손으로 숫자를 적지 않는다). API가 준비되면 화면은 API만 쓰고, 이 파일은 테스트에만 남긴다
- API 호출은 `web/src/api.ts` 한 곳에 모은다. 오류 응답은 `{"detail": "한국어 문장"}`이고 이 문장을 그대로 보여 준다

## 구조
기준 화면은 1440×900이고 최소 폭은 1024px이다.

```
┌──────────────────────────────────────────────────────────────┐
│ 안테나 S11 도우미    [측정] [판정] [이력]                     │ 위 띠, 높이 56
├────────────┬─────────────────────────────────────────────────┤
│ 안테나     │  (고른 탭의 화면)                                │
│  목록      │                                                  │
│ + 안테나   │  판정 탭:  ┌ S11 그래프 ──────┐ ┌ 판정 카드 ──┐  │
│   추가     │            │                  │ │             │  │
│ ────────── │            └──── 1.35 ────────┘ └──── 1 ──────┘  │
│ 측정 횟수  │                                                  │
│ 최근 공진  │                                                  │
│ 최근 판정  │                                                  │
└────────────┴─────────────────────────────────────────────────┘
  사이드바 280    본문 여백 24(위아래) 32(좌우)
```

- **위 띠**: 앱 이름과 탭. 탭은 측정 / 판정 / 이력(p4b에서 관리가 붙는다). 탭 이름과 안내문에 번호(①②③, "2-가")를 쓰지 않는다. 지금 탭은 채운 색으로 표시한다
- **사이드바**(왼쪽에 고정): 안테나 목록, 눌러야 펼쳐지는 "+ 안테나 추가"(이름, 종류, 목표 주파수), 고른 안테나의 측정 횟수 · 최근 공진 · 최근 판정. 요약은 그 안테나의 측정 목록(`limit=200`)에서 만든다: 횟수는 행 수(200건이 꽉 찼으면 "200회 이상"), 최근 공진과 최근 판정은 맨 앞 행의 값만 쓴다. 이 계산은 순수 함수로 둔다
- 처음 열면 목록의 첫 안테나가 골라져 있다. 안테나를 추가하면 그 안테나가 골라지고 추가 폼은 다시 접힌다(펼친 동안 버튼 글자는 "추가 닫기"). 추가 폼: 제목 "새 안테나 추가", 이름(예시 글 "예: 모노폴 B"), 종류(기본 모노폴), 목표 주파수(MHz, 기본 433), 버튼 "안테나 추가"
- 모든 화면의 제목 아래에 고른 안테나를 "{이름} · 모노폴 · 목표 433 MHz"처럼 보여 준다. 요약 상자의 제목은 "{이름} 요약", 값이 없으면 "—", 공진은 소수 2자리
- 안테나는 사이드바에서만 고른다. 다른 안테나를 고르면 열려 있던 카드는 비운다. 측정이 끝나거나 안테나가 바뀌면 요약을 다시 읽는다
- **안테나 추가도 고르기와 같은 길로 지나간다**: 추가한 뒤 고를 때 다른 안테나의 카드를 비운다(안 비우면 사이드바는 B인데 카드와 다시 측정은 A가 된다). 측정하는 동안에는 "+ 안테나 추가"와 그 폼을 끈다
- **안테나 목록은 서버가 기준이다.** 추가, 이름 수정, 삭제 뒤에는 `/api/antennas`를 다시 읽어 목록을 통째로 바꾼다(다시 읽는 동안에는 앞의 목록을 그대로 보여 준다). 화면이 "지운 id"를 따로 기억해 걸러 내지 않는다(같은 id가 다시 쓰이면 새 안테나가 숨는다)
- **입력은 안테나에 딸려 있다.** 고른 안테나가 바뀌면(사이드바, 추가, 삭제 뒤 넘어감) 도체 길이, 바꾼 것, 측정 오류 문구를 비운다. 같은 안테나 안에서는 길이가 측정과 탭 이동 뒤에도 남는다. 패치 안테나에는 길이를 보내지 않는다. 다른 카드를 열 때도 앞의 측정 오류 문구를 지운다
- 추가 폼은 보내기 전에 화면에서 검사한다(순수 함수): 이름이 비면 "안테나 이름을 입력해 주세요", 목표가 0보다 큰 수가 아니면 "목표 주파수를 숫자로 입력해 주세요 (MHz)". 검사에 걸리면 보내지 않는다(서버의 오류문에는 `target_mhz` 같은 식별자가 들어 있다)
- 요약에는 "최근 측정" 줄을 두고 가장 최근 측정의 **출처 배지**를 보여 준다(합성 샘플로 잰 결과가 최근 판정으로 보일 때 합성임이 드러나야 한다)
- **측정**: 카드를 여러 개 늘어놓지 않고 한 판에 행을 차례로 둔다. 행은 왼쪽 200px에 이름과 짧은 안내, 오른쪽에 입력이고 행 사이는 가는 선으로 나눈다
  1. 도체 길이(선택, 모노폴 안테나를 골랐을 때만 보임). 안내: "급전점에서 도체 끝까지 잰 길이입니다. 비워 두면 목표 주파수만으로 판정합니다." 비우면 보내지 않는다. 측정 뒤에도 값이 남는다(자르거나 덧붙였을 때만 고친다). 숫자가 아닌 글이면 보내지 않고 "숫자만 입력해 주세요"라고만 알린다(`lengthInput.ts`). 범위는 서버가 검사한다
  2. Calibration(안내: "VNA 교정"): "VNA에서 교정함"("VNA 본체에서 cal을 마쳤습니다") / "모름 / 안 함"("교정하지 않았거나 모릅니다"). 처음 값은 "모름 / 안 함"이고, 고른 값은 탭을 오가도 유지된다
  3. 측정 방법: 하나만 골라 그 입력만 보인다. 이번에는 `CSV 파일`뿐이고(p6에서 `VNA (USB)`가 앞에 붙어 기본값이 된다), "장비 없이 연습하기 (합성 샘플)"을 눌러야 `합성 샘플 (연습)`이 나타난다. 샘플 목록에는 샘플의 종류와 목표 주파수를 함께 보여 준다(판정은 고른 안테나로 한다). 보이는 방법 목록은 순수 함수(`measureMethod.ts`)가 정한다
- 안테나가 하나도 없으면 측정 화면은 "왼쪽에서 측정할 안테나를 먼저 추가해 주세요."만 보여 준다(입력 행을 그리지 않고, p6의 포트 목록도 요청하지 않는다)
- **판정**: 왼쪽에 S11 그래프, 오른쪽에 판정 카드를 1.35 : 1 폭으로, 같은 높이로 둔다. 측정이 끝나면 이 탭으로 넘어간다
- 판정 화면 머리에 안테나, 출처 배지, 측정 시각(ISO 시각의 `T`를 빈칸으로)을 보여 준다. 측정이 없으면 "아직 측정이 없습니다. 측정 화면에서 시작하거나 이력에서 골라 주세요."
- 판정 카드의 구획 제목은 "원인과 할 일"과 "측정값"이다. 진단 한 건 안의 항목 이름은 "할 일", "근거", "설명". 진단이 여러 개면 "1 / 3"처럼 몇 번째인지와 "← 이전 원인", "다음 원인 →" 버튼을 둔다. `remeasure`의 note는 진단과 측정값 사이에 둔다
- 판정 카드는 서버가 준 문자열을 **그대로** 표시한다. 프론트에서 수치를 다시 계산하거나 문장을 만들지 않는다. 순서는 상태 표시 + headline → diagnoses(title, action, evidence, guide. 여러 개면 한 번에 하나씩 넘겨 본다) → status. `remeasure`가 있으면 그 `note`를 보여 준다(범위를 채우는 버튼은 p6에서 붙인다. 이 칸이 없는 카드도 있다)
- 카드 아래에 "AI 튜터에게 설명 듣기" 버튼과 "질문하기" 입력칸 자리를 둔다(p5에서 연결, 그때까지는 비활성). 생성된 글에는 "AI 설명(참고용)", 질문의 답에는 "AI가 고른 설명" 표시를 붙인다
- **이력**: 고른 안테나의 측정 목록(시각, 출처, 단계, 공진 주파수)과, 한 건을 누르면 오른쪽에 그 카드 보기까지. `limit=200`으로 요청한다. 시각을 누르면 카드가 열리고, 고르기 전에는 "목록에서 측정 한 건을 골라 주세요.", 측정이 없으면 "이 안테나의 측정이 아직 없습니다. 측정 화면에서 시작해 주세요." 카드 옆의 "그래프와 함께 보기 →"는 그 측정을 판정 탭에서 연다. 비교와 추이 그래프는 p7에서 만든다

## 낱말
화면에 `name`, `kind`, `target_mhz`, `vna`, `unknown` 같은 식별자를 보이지 않는다. 낱말은 `labels.ts` 한 곳에 둔다.

| 값 | 화면 |
|---|---|
| 장비 | "VNA" (코드 식별자와 파일 이름은 `saa2` 그대로) |
| `kind` | `monopole` 모노폴, `patch` 패치 |
| `cal_mode` | `vna` "VNA에서 교정함", `unknown` "모름 / 안 함". 카드의 "교정: …" 줄과 같은 낱말인지 테스트한다 |
| `stage` → 상태 | `good` 양호(○), `narrow`·`offtarget` 주의(△), `unmatched`·`none` 문제(×), `invalid`는 문제 색에 "측정 오류" |
| `source` → 배지 | `usb` "VNA 측정"(●), `csv` "CSV"(▤), `synthetic` "합성 데이터"(◇), `stored` "저장된 측정"(▣. 원래 출처를 알 수 없으므로 실측이라고 쓰지 않는다) |

- 상태색은 카드의 `stage` 값으로만, 배지는 `source` 값으로만 정한다. 색만으로 구분하지 않고 기호와 글자를 함께 쓴다
- 출처 배지는 항상 보이게 한다. 합성 샘플을 숨겨 두어도 "합성 데이터" 배지는 그대로 붙는다

## 모양
`web/src/index.css` 한 파일에 색 변수와 공통 클래스를 둔다. 컴포넌트에 색 값을 직접 쓰지 않는다.

| 쓰임 | 값 |
|---|---|
| 바탕 / 면 / 테두리 | `#f4f6f9` / `#ffffff` / `#d5dbe3` |
| 글자 / 흐린 글자 | `#18212c` / `#566170` |
| 강조(버튼, 지금 탭, 고른 안테나) | `#1f5fbf`, 그 위 글자 `#ffffff` |
| 양호 글자·테두리 / 바탕 | `#176b3f` / `#e3f3ea` |
| 주의 글자·테두리 / 바탕 | `#8a5200` / `#fff1cf` |
| 문제 글자·테두리 / 바탕 | `#b3261e` / `#fce7e5` |
| 합성 데이터 글자·테두리 / 바탕 | `#5b3a99` / `#f0eafa` (테두리는 점선) |
| 중립 바탕(꺼진 버튼, 고르는 띠) | `#e9edf2` |

- 글꼴: `15px/1.5 system-ui, 'Apple SD Gothic Neo', 'Malgun Gothic', 'Noto Sans KR', sans-serif`. 화면 제목 28px, 카드 제목 18px, 작은 글 13px
- **판정 카드의 headline은 28px로 화면에서 가장 크다.** 카드 테두리는 상태색 2px
- 면(카드): 흰 바탕, 1px 테두리, 모서리 12px, 안쪽 여백 24px. 면 사이 간격 24px. 그림자는 쓰지 않는다
- 버튼: 강조색 바탕에 흰 글자, 모서리 8px, 굵은 글씨. 보조 버튼은 흰 바탕에 강조색 글자와 테두리. 꺼진 버튼은 중립 바탕. "+ 안테나 추가"는 점선 테두리
- 배지와 상태 표시: 알약 모양(모서리 999px), 13px 굵은 글씨, 1.5px 테두리
- 진단 한 건: 바탕색 면(모서리 8px) 안에 할 일 → 근거 → 설명 순서. 항목 이름은 13px 흐린 굵은 글씨, 내용은 16px
- 안내(로딩, 빈 목록): 점선 테두리에 흐린 글자. 오류는 문제색 테두리와 바탕에 굵은 글씨, "다시 시도" 버튼
- 키보드 초점은 강조색 3px 외곽선으로 보인다

## 규칙
- 측정 요청이 진행되는 동안에는 다른 탭으로 이동할 수 없고 안테나도 바꿀 수 없다. 이력에서 여러 건을 빠르게 누르면 마지막에 누른 측정만 표시한다(늦게 온 응답은 버린다)
- 컴포넌트와 함수는 40줄 이하. 큰 배열에 `Math.min(...배열)` 같은 전개를 쓰지 않는다(12만 점쯤에서 `RangeError`)
- 측정하는 동안 버튼 글자는 "측정하는 중…". CSV 입력의 이름은 "CSV 파일 (UTF-8, 2 MB 이하)", 버튼은 "업로드하고 측정"과 "선택한 샘플로 측정"이고 파일이나 샘플을 고르기 전에는 꺼 둔다
- 오류 문장: 요청 자체가 실패하면 "서버에 연결할 수 없습니다. 서버가 켜져 있는지 확인한 뒤 다시 시도해 주세요.", 응답을 읽을 수 없으면 "서버 응답을 읽을 수 없습니다. 앱 서버 주소가 맞는지 확인해 주세요." health와 안테나 목록을 다 읽기 전에는 사이드바를 포함해 아무 화면도 그리지 않고, 실패하면 오류와 "다시 시도"(둘 다 다시 읽는다)만 보여 준다
- 로딩, 빈 목록, 서버 꺼짐 상태를 각각 만든다. 서버 꺼짐은 요청 자체가 실패한 경우와, 개발 서버 프록시가 `detail` 없는 5xx를 돌려준 경우를 모두 포함한다
- `index.html`의 `lang`은 `ko`, 제목은 앱 이름으로 바꾼다
- Vite 템플릿의 데모 화면과 자산(데모 스타일, `hero.png`, 로고 svg, `public/icons.svg`, `web/README.md`)은 지운다
- 새 npm 패키지는 물어보고 추가
- 대역폭·VSWR 고급 설정과 패치 안테나의 치수 입력은 만들지 않는다

## S11 그래프
- SVG로 직접 그린다. 가로축 MHz, 세로축 dB(위가 0)
- 목표선은 `antenna.target_mhz`, 공진 표시는 응답의 `resonance_mhz`와 `s11_db`로 그린다(`null`이면 그리지 않는다). 스윕에서 최솟값을 찾아 표시하지 않는다. -10 dB 선을 그린다
- 세로축 범위는 0 dB부터 스윕 최솟값까지로 하되, 아래쪽은 -30 dB보다 얕지 않고 -60 dB보다 깊지 않게 한다. 범위를 벗어난 값(0 dB보다 큰 값 포함)은 축 끝에 붙여 그린다
- 좌표 계산(값 → 화면 좌표, 축 범위)은 JSX가 없는 `.ts` 파일의 순수 함수로 둔다
- 곡선은 글자색 2px, 목표선은 강조색 점선, -10 dB 선은 흐린 점선, 공진 표시는 주의색 점

## 테스트
새 패키지 없이 Node 내장 테스트 러너를 쓴다. 테스트 파일은 `web/src/*.test.ts`, 실행은 `node --test web/src/*.test.ts`(`web/package.json`의 `test` 스크립트로도 등록). JSX가 없는 `.ts` 파일만 테스트하고, import에는 `.ts` 확장자를 쓴다.
- `stage` 6개 값 → 상태색과 낱말, `source` 4개 값 → 배지, `cal_mode` 2개 값 → 낱말. 낱말에 영어 식별자가 없는지
- 사이드바 요약: 빈 목록, 1건, 200건(꽉 찬 목록), 맨 앞 행의 공진이 `null`인 경우, 맨 앞 행의 출처
- 안테나가 바뀌면 길이·바꾼 것·오류가 비워지는지, 같은 안테나면 길이가 남는지, 패치면 길이를 보내지 않는지
- 추가 폼 검사: 빈 이름, 빈 목표, 글자, 0, 음수
- 지운 안테나와 같은 id의 새 안테나가 목록에 보이는지
- 도체 길이 입력: 빈 값, 숫자, 숫자가 아닌 글
- 측정 방법 목록: 연습을 누르기 전과 뒤
- 그래프 좌표: 축 양 끝 값, 세로축 범위의 하한 두 경계(-30, -60), 범위를 벗어난 값이 축 끝에 붙는지, 1점뿐인 스윕과 `resonance_mhz`가 `null`인 경우에 예외가 없는지
- fixture가 `types.ts`의 타입으로 컴파일되는지(빌드의 타입 검사가 잡는다)
- 오류 응답 해석: `detail`이 있는 422, `detail`이 없는 5xx, 요청 실패, 200인데 JSON이 아닌 응답
- 요청 경로와 본문(합성 측정, 안테나 추가, CSV 업로드 필드, 이력 쿼리, `length_cm`을 넣은 경우와 뺀 경우)을 가짜 `fetch`로 검사
- 20만 점 스윕의 축 범위 계산에 예외가 없는지

통과 검사: `node --test web/src/*.test.ts` 통과, `npm --prefix web run lint` 통과, `npm --prefix web run build` 성공. 그리고 서버와 화면을 실제로 띄워 ① 합성 샘플 선택 → 그래프와 카드 표시 ② `open` 샘플처럼 공진이 없는 측정에서 공진 표시 없이 그려짐 ③ 목표가 범위 밖인 안테나로 측정하면 서버의 한국어 안내가 보임 ④ 서버를 끄면 오류 안내 표시 ⑤ 1440×900 창에서 사이드바와 판정 화면이 가로로 넘치지 않음. 확인용 서버는 빈 포트와 임시 DB로 띄운다. 직접 띄워 볼 수 없는 항목은 "사람이 확인"으로 남기고 통과로 적지 않는다.
