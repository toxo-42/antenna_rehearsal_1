# P9 — 안정화 (60분)

새 기능을 만들지 마. 먼저 `README.md`를 써 줘: 필요한 것(uv, Node), 설치, 실행, 테스트, 환경 변수(`OLLAMA_MODEL`, `OLLAMA_EXPLAIN`, `APP_MODE`), 합성 데이터 안내. 적는 명령은 전부 실제로 실행해 확인한 것만(실행해 보지 않은 OS의 명령은 적지 않고, 예시 id는 실제로 있는 것을 쓴다). 코드 블록 안에 `#` 주석을 넣지 않는다(대화형 zsh에 붙여 넣으면 깨진다). "인터넷으로 나가지 않는다", "읽기만 한다", "다르면 버린다" 같은 보장은 테스트나 코드로 확인한 범위까지만 쓴다. 그다음 아래를 실제로 실행해 통과/실패 표로 보고하고, 실패만 고쳐 줘.

1. Ollama 꺼짐 2. SAA-2 뽑힘 3. 측정 중 뽑기 4. 빈 CSV 5. 열이 없는 CSV 6. 목표가 범위 밖 7. 이력 0건 8. 측정 버튼 연타 9. 새로고침 10. 새 폴더에 clone 후 README만 보고 실행 11. `APP_MODE=demo`로 실행(`demo.db` 없을 때와 있을 때)

직접 할 수 없는 항목(2, 3 등)은 "사람이 확인"으로 남기고 통과로 적지 마. 서버 응답만 본 항목은 "서버 통과 / 화면은 사람이 확인", 흉내 낸 항목(닫힌 포트로 Ollama 꺼짐을 대신한 것 등)은 "시뮬레이션"이라고 적어. 실행한 명령과 출력은 파일로 남겨(검토자는 대화를 못 본다). 확인용 서버는 비어 있는 포트와 새 DB로 띄워. 고칠 때마다 실패를 재현하는 테스트를 먼저 추가해.
