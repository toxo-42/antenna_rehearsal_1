# 대회용 프롬프트 사용법

코드는 가져가지 않는다. 이 폴더의 글만 붙여 넣어 빈 폴더에서 만든다. 기존 저장소는 참조하지 않는다.
**아직 리허설하지 않았다 (STEP 5에서 검증).** P1·P2의 기대값은 프롬프트 글만 보고 구현해 14/14 일치를 확인했다. 패치 4행(P1)은 2026-11-22에 추가했고 P1 수치만 같은 방식으로 확인했다. 패치의 P2 key 순서는 미확인이다. 실제 Claude Code 세션에서의 재현, 화면, USB는 미확인이다.

## 순서
1. 빈 폴더에 `CLAUDE.template.md` 내용을 `CLAUDE.md`로 저장
2. `p0` → `p1` → `p2` → `p3` 순서로 한 세션에 하나씩. 동시에 여는 세션은 최대 2개: `p4`는 p2 무렵부터 git worktree에서 병렬
3. p3과 p4가 끝난 뒤 `p6` → `p5` → `p7` → `p8` → `p9` (시각은 `notes/step3_timeline.md`)
4. 막히면 `recovery.md`

## 공통 규칙
- 프롬프트 1개 = 새 세션 1개. 끝나면 통과 검사 → 커밋 → `/clear`
- 통과 검사의 **기대값을 고쳐서 통과시키지 않는다.** 기대값이 이상하면 멈추고 사람이 판단한다
- 같은 문제로 2번 실패하면 `recovery.md`의 R1

## 차후 확장 (대회 범위 밖)
대회에서는 LLM이 설명 번호만 고른다. 아래는 그 뒤에 붙일 수 있는 것이고, 어느 것도 "숫자·방향·결론은 코드가 만든다"는 원칙을 바꾸지 않는다.
- 설계 가이드 문서(35단원) 검색: 고른 설명에 관련 단원을 **원문 그대로** 함께 보여 준다
- 문장 생성: 판정 카드를 입력으로 받아 쉬운 말로 풀어 쓴다. 카드의 수치·방향과 다른 내용이 나오면 버리는 검사를 코드에 둔다
- 조정량을 mm로: 현재 도체 길이를 입력받아 %를 길이로 바꾼다
- `QuestionRouter` Protocol 뒤에 구현을 추가하는 방식으로 붙인다. 판정 코어(p1·p2)는 건드리지 않는다
